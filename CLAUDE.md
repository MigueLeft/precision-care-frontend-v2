## Stack & Configuration

- **React 19** + **TypeScript 6** + **Vite 8** (uses Rolldown under the hood)
- **Package manager**: pnpm (use `pnpm`, not `npm` or `yarn`)
- **React Compiler** is enabled via `babel-plugin-react-compiler` + `@rolldown/plugin-babel` in `vite.config.ts`. This means manual `useMemo`/`useCallback` memoization is generally unnecessary — the compiler handles it. Do not add manual memoization unless there's a specific reason.
- **TypeScript** is in bundler mode (`moduleResolution: bundler`, `noEmit: true`). Type-checking runs as a separate step (`tsc -b`), not through Vite.
- **ESLint** config (`eslint.config.js`) uses flat config format with `typescript-eslint`, `eslint-plugin-react-hooks`, and `eslint-plugin-react-refresh`. `noUnusedLocals` and `noUnusedParameters` are enforced by the TypeScript compiler.

## Bootstrap architecture

Entry point: `src/main.tsx` → `<QueryClientProvider>` → `<ThemeProvider>` → `src/App.tsx` → `<RouterProvider>`

The router context (`RouterContext`) carries `isAuthenticated` (provided by `useSession` from `src/features/auth`). Auth guard logic lives in `beforeLoad` of each route — see `src/routes/index.tsx` and `src/routes/_auth/route.tsx`.

Router definition is in `src/router.ts` (not in `main.tsx`). The `routeTree.gen.ts` is auto-generated by the Vite plugin — never edit it manually.

## Architecture

- Usaras principios SOLID en todo el codigo y las mejores practicas de react
- Todas las solicitudes deben tener su toast y mostrar los errores correspondientes 
- Las validaciones de zod deben coincidir con los DTOs de el backend 
- Siempre que crees un hook para obtener informacion de la API un GET, POST, PUT o DELETE debes revisar los DTOs para ver que todo coincida en el front
- Todo deben estar en ingles, lo unico en español son los comentarios
- Siempre usa el mcp de context7 
- No hace falta que crees tests salvo que lo pida 
- Al crear componentes debes siempre tomar en cuenta el Higher-Order Component (HOC)
- Los componentes no deben tener demasiadas lineas de codigo para que este sea facil de mantener 
- Utilizaras esta arquitectura para el proyecto "Feature-Sliced Hybrid"
En 2026, la industria ha convergido en una mezcla entre Atomic Design (para la UI base) y Feature-Based Architecture (para la lógica de negocio).

Estructura de Carpetas
src/
├── assets/          # Imágenes, fuentes, estilos globales.
├── components/      # UI Pura (Átomos/Moléculas): Botones, Inputs, Modals (sin lógica de API).
├── features/        # El corazón del proyecto.
│   └── auth/        # Cada feature es un "mini-app"
│       ├── components/  # Solo componentes de Auth (LoginForm, etc.)
│       ├── hooks/       # useAuth, useSession
│       ├── services/    # Llamadas a API/TanStack Query
│       ├── types/       # Interfaces de TS para esta feature
│       └── index.ts     # Punto de entrada (Barrel export)
├── hooks/           # Hooks globales (useLocalStorage, useWindowSize).
├── store/           # Estado global (Zustand, Jotai o Redux).
├── utils/           # Funciones puras (formateo de fechas, validaciones).
└── pages/           # Solo para el enrutado y composición de features.

## Arquitectura y Estructura
- **Feature-First:** Todo lo relacionado con una lógica de negocio debe ir en `src/features/{feature_name}`. No mezcles lógica de diferentes dominios.
- **Principio de Exportación:** Una feature solo debe exponer lo necesario a través de su `index.ts`. No permitas importaciones profundas como `import { X } from '@/features/auth/components/Button'`.
- **UI vs. Negocio:** Los componentes en `src/components` deben ser presentacionales ("tontos"). La lógica de datos reside en `src/features` o Hooks.

## Estándares de Código
- **Tamaño de Componente:** Límite máximo de 150 líneas por archivo. Si excede, extrae sub-componentes o lógica a un Custom Hook.
- **Hooks sobre useEffect:** Prioriza el uso de `TanStack Query` para fetch de datos o `useActionState` (React 19). `useEffect` solo para sincronización con sistemas externos.
- **TypeScript:** Prohibido el uso de `any`. Usa interfaces estrictas. Prefiere `type` para props y `interface` para modelos de datos de API.
- **Composicion:** Prefiere `children` para evitar el "Prop Drilling".

## Reglas de React 19 (Moderno)
- Usa el compilador de React; evita `useMemo` y `useCallback` manuales a menos que sea una optimización extrema.
- Implementa `Suspense` para estados de carga y `ErrorBoundary` por cada feature principal.

## Verificación antes de finalizar
- Ejecuta `npm run lint` y `tsc --noEmit` después de cada cambio significativo.
- Los tests unitarios deben estar co-localizados (ej. `LoginForm.test.tsx` junto a `LoginForm.tsx`).

## Reglas de Material UI (MUI)
- **Tema Centralizado:** No uses colores fijos (ej. `#FF0000`). Usa siempre `theme.palette.primary.main` o valores del tema.
- **SX Prop vs Styled Components:** - Usa la prop `sx` para ajustes pequeños de espaciado o alineación (margin, padding).
    - Para componentes complejos y reutilizables, usa la API `styled()` de MUI para mantener el JSX limpio.
- **Abstracción de Componentes:** No permitas que Claude use componentes de MUI directamente en las Features si se van a repetir. Crea un "wrapper" en `src/components`.
    - *Ejemplo:* Crea `src/components/AppButton.tsx` que encapsule el `Button` de MUI con tus variantes por defecto.
- **Data Display:** Prefiere siempre `Stack` y `Grid2` (MUI v6+) para layouts en lugar de `Box` con flexbox manual.
- **Formularios:** Integra `react-hook-form` con los componentes de MUI usando el patrón `Controller` de la librería de formularios.

El "Patrón de Oro": El Componente Controlado
// Ejemplo de lo que se debe seguir
import { Controller } from 'react-hook-form';
import { TextField } from '@mui/material';

// En el componente de feature:
<Controller
  name="email"
  control={control}
  render={({ field, fieldState: { error } }) => (
    <TextField
      {...field}
      label="Correo Electrónico"
      error={!!error}
      helperText={error?.message}
      fullWidth
    />
  )}
/>

## Reglas de TanStack Router (Type-Safe Routing)
- **File-Based Routing:** Crea las rutas dentro de `src/routes/`. Usa el sufijo `.lazy.tsx` para componentes de página que no necesiten carga de datos crítica en el bundle inicial.
- **Type Safety:** Nunca uses `<a>` para navegación interna. Usa exclusivamente el componente `<Link>` de `@tanstack/react-router` para garantizar que las rutas sean válidas.
- **Validación de Search Params:** Usa la API `validateSearch` con **Zod** para definir y validar los parámetros de la URL (filtros, paginación, etc.).
- **Loaders:** Utiliza la función `loader` de la ruta para pre-cargar datos de la API antes de que el componente se renderice.
- **Integración con TanStack Query:** Dentro de los loaders, utiliza `queryClient.ensureQueryData()` para evitar peticiones duplicadas.
